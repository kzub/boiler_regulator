# Boiler Regulator Web App

Mobile-first панель для контроллера клапанов. Выбран дизайн A «Домашняя панель»;
тема следует системной (auto). Приложение не меняет прошивку Arduino.

## Запуск в Docker

На домашнем сервере создайте `.env` из примера и укажите IP Arduino:

```sh
cp .env.example .env
# отредактируйте CONTROLLER_BASE_URL в .env
docker compose up -d --build
```

Панель будет доступна по `http://<адрес-сервера>:8080`. Она рассчитана только на
доверенную LAN. Не публикуйте этот порт в интернет без отдельного reverse proxy,
TLS и аутентификации.

Полезные команды:

```sh
docker compose logs -f
docker compose pull && docker compose up -d --build
docker compose down
```

Калибровка и последний наблюдавшийся процент открытия сохраняются в named volume
`calibration-data`; его не следует удалять при обычном обновлении. Для резервной
копии можно сохранить содержимое `/data/calibration.json` из контейнера. Если
Arduino перезапустится и вернёт `0` или позицию вне сохранённой шкалы, сервер
пометит шкалу недействительной. При следующей калибровке он измерит MIN/MAX и
вернёт оба регулятора к последним сохранённым процентам открытия. Автоматический
запуск этой процедуры зависит от `AUTO_CALIBRATE`.

На концевике прошивка не измеряет положение, а записывает в счётчик константу:
`500` на одном конце и `9500` на другом. Между ними 9000 шагов, тогда как клапан
проходит около 6000, поэтому шкала «от константы до константы» открывала клапан
примерно в полтора раза сильнее запрошенного (50% превращались в ~75%). Backend
измеряет фактический ход во время калибровки и считает проценты по нему.

Калибровка каждого регулятора — ровно два прохода: MIN, затем MAX (он же измеряет
ход), после чего одна относительная команда возвращает прежнее открытие. Третий
проход MIN больше не нужен. У первого мотора после инверсии DIR константы
записываются наоборот (`min` → `9500`, `max` → `500`), и его счётчик во время
работы выходит за обе константы — backend опирается на последнюю записанную
константу и считает шаги от неё, отдельного переключателя для этого нет.

Формат сохранённой калибровки — schema 4. Файлы прежних версий не читаются: в них
не было измеренного хода. После обновления панель попросит перекалибровку и до
неё клапаны не двигает.

## Развёртывание на NAS (bob)

Контейнер на Synology создаётся через Container Manager. Подготовленный compose,
скрипт синхронизации исходников и пошаговая инструкция лежат в
[`../deploy/bob/`](../deploy/bob/README.md). Панель там слушает порт **8088**
(8080 на bob занят vaultwarden), калибровочные данные хранятся в
`/volume1/docker/dacha-temp/data`, а `AUTO_CALIBRATE` выключен, чтобы
перезапуск контейнера не двигал клапаны сам по себе.

Обновление одной командой — `./deploy/bob/deploy.sh`: копирует исходники,
пересобирает образ, перезапускает контейнер и проверяет, что отвечает уже новая
сборка. Просто «Start» в Container Manager без «Build» оставляет старый образ,
поэтому внизу страницы показаны версия, коммит и время сборки, а
`curl -s http://bob:8088/api/version` отвечает на тот же вопрос из терминала.

## Локальная разработка

Требуется Node.js 22+.

```sh
npm ci
cp .env.example .env
npm run dev
```

В отдельной консоли доступны проверки:

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

Адрес Arduino остаётся только в серверной конфигурации: браузер обращается к
`/api`, поэтому CORS прошивки не используется. Команды MIN/MAX и процентные
команды подтверждают лишь приём, а не достижение механической позиции. Сервер не
повторяет их автоматически.

Backend не выполняет фонового polling Arduino в idle-режиме. Обычный запрос
`/status` приходит от открытой панели раз в 5 секунд, а во время движения — раз
в 300 ms. Явно запущенная калибровка является исключением: ей нужен временный
частый polling для безопасного завершения этапов. Изменения счётчиков, сделанные
штатным энкодером контроллера, сохраняются как новое последнее положение.

## Диагностика

- «Нет связи» — проверьте IP, питание и доступность Arduino из Docker-сети.
- «Шкала не откалибрована» — дождитесь автоматической процедуры или нажмите
  «Перекалибровать».
- Значение `—` у температуры означает недостоверный ответ датчика (`-127°C`,
  стартовые `85°C` и физически невозможные величины скрываются).
- Поворот вала вручную без запуска мотора нельзя обнаружить текущим
  оборудованием. После него выполните ручную перекалибровку.

Подтверждённый mapping датчиков: `fl1` — первый этаж, `fl2` — второй этаж,
`boiler` — температура воды котла, `room` — бойлерная комната. Смысл MIN/MAX
следует подтверждать по чек-листу в плане.
